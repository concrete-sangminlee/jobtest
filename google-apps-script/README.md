# PC 없이 사용하는 Google 수집 연결

Google Apps Script가 **공개 채용 목록만** 읽어 반환하고, GitHub Actions가 기존 파싱·중복 방지·Slack 발송을 담당합니다.
Google 프로젝트에는 Slack 웹훅이나 GitHub 토큰을 넣지 않습니다. Google 웹앱 주소는 공개 목록을 반환하는 주소입니다.
사용자의 Google 계정에서 배포해야 하며, 계정/조직 정책에 따라 공개 웹앱 배포가 제한될 수 있습니다.

이 경로는 Google의 무료 Apps Script 실행 할당량을 사용합니다. 예약 주기 3회/일 기준으로 적은 요청만 발생합니다.
무료 서비스의 할당량·정책은 바뀔 수 있으며, 사이트가 Google의 요청도 거부하면 이 경로 역시 사용할 수 없습니다.
**이 저장소의 모의 테스트 통과는 Google에서 실제 수집에 성공했다는 뜻이 아닙니다. 먼저 아래 연결 검증을 통과해야 합니다.**

## 한 번만 설정

1. https://script.google.com/home 에서 **새 프로젝트**를 만듭니다.
2. 기본 `Code.gs` 내용을 이 폴더의 `Code.gs` 내용으로 바꿉니다.
3. 프로젝트 설정에서 `appsscript.json` 표시를 켜고, 이 폴더의 manifest 내용을 복사합니다.
   외부 HTTP 요청 권한만 사용합니다.
4. 함수 목록에서 **testConnection**을 선택해 실행하고 본인 계정의 외부 요청 권한을 승인합니다.
   실행 로그에 `연결 성공: 공고 링크 N개`가 나와야 합니다. 실패하면 아직 GitHub 설정을 바꾸지 마세요.
5. **배포 → 새 배포 → 웹 앱**에서 실행 사용자는 **나**, 접근 권한은 **모든 사용자(Anyone)**로 선택합니다.
   조직 정책 때문에 이 선택이 없으면 이 방법을 바로 사용할 수 없습니다.
6. 배포 결과의 `https://script.google.com/macros/s/.../exec` 주소를 복사합니다. `/dev` 주소는 사용하지 않습니다.
   이 주소를 담당 에이전트에 전달하면, GitHub 수동 검증 입력 `google_apps_script_url`로 실제 연결을 검증할 수 있습니다.
   웹앱 주소에는 Slack 토큰이나 Google 비밀번호가 포함되지 않습니다. 이런 비밀정보는 전달하지 마세요.
7. GitHub 저장소 **Settings → Secrets and variables → Actions → Variables**에
   `GOOGLE_APPS_SCRIPT_URL`을 만들고 웹앱 주소를 값으로 넣습니다. 선택적으로 `FETCH_MODE=google`을 설정하면
   Google 경로만 검증할 수 있습니다. 기본 `auto`는 직접 수집 → Google → 브라우저 순서입니다.
8. 개선된 `Check hibrain.net Job Postings` 워크플로를 `dry_run=true`로 실행합니다.
   성공한 뒤 운영 브랜치에 반영하면 기존 GitHub 예약 실행이 이 경로를 사용합니다.

이 작업에서는 Google에 별도 시간 트리거를 만들지 않습니다. 예약은 기존 GitHub 작업이 계속 담당합니다.
Google 코드 변경 후에는 **배포 관리 → 수정 → 새 버전**으로 웹앱 배포도 갱신해야 합니다.

## 문제 확인

- `testConnection`에서 403: Google 실행 위치도 사이트가 거부한 것입니다. 코드가 성공으로 숨기지 않습니다.
- 웹앱 접속 시 로그인 화면: 공개 웹앱 접근 설정 또는 `/exec` 주소를 확인합니다.
- GitHub에서 연결 실패: 웹앱 주소, 배포 버전, Google 실행 로그를 확인합니다. 응답이 10분 이상 오래됐거나 잘못된 목록이면 실패 처리합니다.
- 수집 성공 후 Slack 실패: 기존 `SLACK_WEBHOOK_URL` 설정을 확인합니다. Google 프로젝트로 웹훅을 옮길 필요는 없습니다.

웹앱은 고정된 하이브레인 주소만 요청합니다. 호출자가 전달한 URL이나 헤더를 실행하지 않습니다.
프로젝트를 공개 저장소에 복사할 때도 계정 토큰이나 웹훅을 코드에 추가하지 마세요.
